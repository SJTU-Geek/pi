# pi mobile demo (Capacitor + embedded Node.js)

Scaffold for running pi inside the embedded Node.js runtime on a phone, via
[Capawesome's Capacitor NodeJS plugin](https://capawesome.io/docs/sdks/capacitor/nodejs/)
(ships **Node.js 18.20.4** on Android and iOS). This directory is a standalone
npm project — intentionally **not** part of the pi npm workspaces.

## What already works

- The `feat-mobile` branch makes pi run on Node 18.20 (see commit
  "feat: support Node 18 runtimes"); `npm run smoke:node` here bundles the
  Node-side demo and runs it on whatever Node is in `PATH` — verified on
  18.20.8 and 24.20.0.
- `npx cap add android` + `npx cap sync android` succeed; the plugin is
  detected and the web assets (including `www/nodejs/`) are copied into the
  Android project.
- `www/nodejs/` is the embedded Node project that ships inside the app:
  `pi-bundle.js` (esbuild CJS bundle of `src/node-main.js` + `@earendil-works/pi-ai`)
  plus its `package.json` (`main: pi-bundle.js`). It proves the full
  streaming pipeline on the embedded runtime with the in-memory faux
  provider — no network or API key required.

## Layout

```
capacitor.config.json   appId/appName, webDir=www, Nodejs.startMode=manual
www/index.html          WebView UI: start runtime, send prompt, show events
www/nodejs/             embedded Node project (nodeDir default), ships with web assets
src/node-main.js        Node-side entry: require("bridge") + faux provider stream
android/                generated by `npx cap add android`
```

The messaging bridge is **event-based**, not stdin/stdout: the webview calls
`Nodejs.send({ eventName, args })`, the Node side answers with
`channel.post(eventName, ...args)` (from `require("bridge")`), and the
webview receives them via `Nodejs.addListener("message", ...)`.

## Local smoke test (no Android SDK needed)

```bash
npm install                              # use CAPACITOR_NODEJS_SKIP_DOWNLOAD=1 if GitHub is unreachable
npm run smoke:node                       # bundles pi-ai and runs the faux stream on local Node
```

## Building and running on a device

Requires Android SDK + platform tools (Java 17 is sufficient):

```bash
npm run cap:open                         # opens Android Studio, then Run
# or headless:
cd android && ./gradlew assembleDebug
```

The Gradle build downloads the nodejs-mobile Android binaries
(`nodejsMobileVersion` in `variables.gradle`, default `18.20.4-capawesome.1`).
On the device: tap **Start Node runtime**, then **Send prompt** — the WebView
should show streamed deltas from the faux provider running inside embedded
Node.

For iOS: the plugin supports Swift Package Manager only (no CocoaPods); the
nodejs-mobile iOS binaries download during `npm install` (set
`CAPACITOR_NODEJS_SKIP_DOWNLOAD=1` to skip, e.g. behind a firewall).

## Known constraints of the embedded runtime (next integration steps)

- **Event bridge ≠ stdio.** pi's coding-agent RPC mode speaks JSON over
  stdin/stdout; wiring it to `bridge` needs a small adapter that shims
  `process.stdin`/`process.stdout` before importing the agent bundle.
- **No `child_process`.** The mobile runtime does not provide it. The full
  coding-agent bundle statically imports it in several modules (bash tools,
  package manager), so a mobile build must stub that module (esbuild alias)
  and the exec-based tools will degrade. `@earendil-works/pi-ai` itself is
  clean — no `child_process`, no native addons.
- **Externals.** The full coding-agent bundle externalizes `jiti` and the
  photon WASM asset; those files must ship inside `www/nodejs/` too.
- Single instance: the runtime starts once per app launch (no `stop()`).
